# 版本管理规范

本文档定义了 EasyProject 移动端的版本号管理规则。

## 版本号格式

遵循 [Semantic Versioning 2.0.0](https://semver.org/) 规范：

```
MAJOR.MINOR.PATCH
```

### 版本号说明

| 字段 | 说明 | 更新时机 |
|------|------|----------|
| MAJOR | 主版本号 | 重大功能变更、架构调整、不兼容更新 |
| MINOR | 次版本号 | 新增功能、向后兼容的功能增强 |
| PATCH | 修订号 | Bug修复、小优化、安全补丁 |

### 示例

- `1.0.0` - 初始版本发布
- `1.0.1` - Bug 修复
- `1.1.0` - 新增功能
- `2.0.0` - 重大更新，不兼容旧版本

## versionCode 规则

Android 平台使用的 `versionCode` 采用以下计算方式：

```
versionCode = MAJOR * 10000 + MINOR * 100 + PATCH
```

### 示例

| versionName | versionCode |
|-------------|-------------|
| 1.0.0 | 10000 |
| 1.0.1 | 10001 |
| 1.1.0 | 10100 |
| 2.0.0 | 20000 |
| 2.5.3 | 20503 |

## 版本更新流程

### 1. 更新版本号

修改 `src/manifest.json`:

```json
{
  "versionName": "1.1.0",
  "versionCode": "10100"
}
```

### 2. 更新日志

在 `docs/CHANGELOG.md` 中记录更新内容。

### 3. Git 标签

```bash
git tag -a v1.1.0 -m "Release v1.1.0"
git push origin v1.1.0
```

### 4. 各平台发布

#### 微信小程序

1. 使用 HBuilderX 或 CLI 编译
2. 上传到微信开发者工具
3. 提交审核
4. 发布上线

#### H5

1. 编译 H5 版本
2. 部署到服务器
3. 更新 nginx 配置

#### Android App

1. 使用 HBuilderX 云打包或本地打包
2. 生成 APK/AAB 文件
3. 上传到应用市场

#### iOS App

1. 使用 HBuilderX 云打包
2. 上传到 App Store Connect
3. 提交审核
4. 发布上线

## 版本命名规范

### 预发布版本

- `1.0.0-alpha.1` - 内部测试版本
- `1.0.0-beta.1` - 公开测试版本
- `1.0.0-rc.1` - 候选发布版本

### 特殊版本

- `1.0.0-hotfix.1` - 紧急修复版本
- `1.0.0-build.123` - 构建版本

## 注意事项

1. **递增规则**: 版本号只能递增，不能回退
2. **唯一性**: 每个 versionCode 在同一应用中必须唯一
3. **审核周期**: 预留足够的审核时间
4. **兼容性**: MINOR 和 PATCH 更新必须保持向后兼容
